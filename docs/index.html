01

What's in the box

One popup, one catalog, no tabs to juggle — built to be read and trusted as much as it is used.

01

564 tools, 18 categories

A real category browser — pick a category, see its count, then search within it. You don't need to know a tool's name to find it.

02

One extension, not twenty

Replace a separate tab, site or extension for every small task. Everything runs from the popup or the side panel, from a single install.

03

Offline-first, zero telemetry

There is no network layer in the extension. Nothing is fetched, phoned home, or loaded remotely — your inputs stay on your machine.

04

Rich, typed output

Text lands in a copyable box; HTML results (markdown previews, palettes, CSS generators, charts) render in a sandboxed preview; images render inline with a download link.

05

Destructive actions are gated

History, cookie and cache cleaners, duplicate-tab closing and auto-close are dry-run by default — they only act after you tick an explicit confirmation.

06

Runs across four browsers

One source tree, assembled per browser. A tool that needs an API a browser doesn't expose is disabled and says so plainly — instead of failing silently.

07

Audited, not just listed

Every tool is executed with realistic input and its output graded. Anything that could not actually work — needing an unbundled library, or an API no browser exposes — was removed instead of shipped as a placeholder.

02

How it works

From toolbar to result in five steps. No setup, no account, no network round-trip.

STEP 01

Open TTB

Click the toolbar icon or press Alt+Shift+T. Open the side panel with Alt+Shift+K.

STEP 02

Browse or search

Filter by category on the left, or type in the search box — Ctrl+K focuses it.

STEP 03

Pick a tool

The panel shows the fields that tool needs: a main input, plus any extra values, switches or file pickers.

STEP 04

Run it

Press Run or Ctrl+Enter. Execution is imported on demand — the catalog renders even if a handler fails.

STEP 05

Use the output

Copy the result, or download it for image and file tools. Everything stays local.

The shape of the code

popup.html / sidebar.html
  ├─ data/tools.js        → globalThis.TTB_CATALOG  (564 entries)
  └─ ui/app.js            → renders the catalog, builds inputs, runs tools
       └─ (on first Run) tools/core.js  → dispatcher
            ├─ text · calc · dev · page · system · security   (core handlers)
            ├─ phase4–6 + t-*.js                              (bundled modules)
            ├─ tools/compat.js                                (namespace + capability layer)
            └─ ui/registry.js                                 (name → handler, inputs)
background.js             → context menu + keyboard commands only
build.mjs + browsers/*.json → per-browser packages (dist/chrome, edge, firefox, safari)

The catalog is separated from execution, so the tool list renders even if a handler or a privileged API fails. Tool execution is imported on demand, and tools/compat.js is the only place that knows about browser differences.

Get started

No build step is required to load the extension — the repository root is a working Chromium extension.

Chromium · Chrome / Edge / Brave / Opera / Vivaldi

Load unpacked in four steps

  1. Clone or download the repository.
  2. Open chrome://extensions (or edge://extensions) and enable Developer mode.
  3. Choose Load unpacked and select the folder containing manifest.json.
  4. Pin TTB, then click the icon or press Alt+Shift+T.

Firefox & Safari

Build per browser

# produce dist/chrome, edge, firefox, safari
npm run build

# Firefox: load dist/firefox/manifest.json
# via about:debugging#/runtime/this-firefox
npm run build:firefox

# Safari: convert the package with Xcode
npm run build:safari

Prebuilt ZIPs for every browser are attached to each successful CI run (Actions → Validate → Artifacts). Requirements: Chrome 127+, Edge 127+, Firefox 121+, Safari 16.4+.

FAQ

Straight answers, including the limitations.

Q Is TTB free and open source?
Yes. TTB is PolyForm Noncommercial licensed — free to use, read, modify and redistribute. See LICENSE.
Q Does it phone home or track me?
No. There is no network layer in the extension: nothing is fetched, phoned home, or loaded remotely. No analytics, no telemetry. Privileged tools use only the permissions declared in manifest.json, and each browser build requests only what that browser can grant.
Q Which browsers are supported?
Chrome 127+, Edge 127+, Firefox 121+ and Safari 16.4+. One source tree is assembled per browser by npm run build. Safari exposes no history, bookmarks, downloads, management, browsingData or fontSettings APIs, so those tools are disabled there and report that — and Safari also needs an Xcode conversion step.
Q Why aren't the PDF and OCR tools here any more?
They don't any more. In v0.11.0 every tool was executed with realistic input and its output graded; the 22 tools that needed an unbundled third-party library (all the PDF tools, OCR, Excel viewer, Prettier, OpenPGP, axe-core) and 7 that no extension can implement were removed from the catalog rather than shipped as placeholders. The evidence is in TOOL_AUDIT.md. No remote code is ever fetched.
Q How do you know the tools actually work?
Each tool is executed with realistic input and its output graded — computed, fixed reference, validated input, needs a browser API, or unavailable. The results are published per tool in TOOL_AUDIT.md and regenerated with npm run audit. Nothing in the catalog is a placeholder.
Q Are destructive tools safe to try?
They do nothing on the first run. History/cookie/cache cleaners, duplicate-tab closing and auto-close report exactly what they would change and ask you to tick “I understand — confirm this destructive action”. Only then does a second Run act.
Q Why do some page tools fail on certain tabs?
Tab, history, cookie, bookmark, download and page tools need the right context. They can fail on restricted pages such as chrome://, the Web Store, or other extensions' pages — which no browser allows scripting.
Q How do I contribute?
Read CONTRIBUTING.md. There's no framework — vanilla JavaScript and browser APIs. npm test runs the smoke test, npm run build assembles all four targets.
